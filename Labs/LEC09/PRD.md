# 소닉 애니메이션 뷰어 개발 요구사항

- 기준 문서: [PRE-PRD.md](./PRE-PRD.md)
- 작업 위치: `Labs/LEC09`
- 작업 브랜치: `LEC09`
- 구현 파일: `sonic_animation_viewer.py`
- 사용 이미지: `sonic-sprite.png`
- 문서 상태: 개발 전 요구사항 및 완료 기준

## 1. 목적

제공된 소닉 스프라이트 시트의 모든 소닉 동작을 순서대로 감상할 수 있는 애니메이션 뷰어를 만든다. 각 동작은 5회 재생하고 1초 정지한 뒤 다음 동작으로 넘어가며, 마지막 동작 이후 처음부터 같은 과정을 무한 반복한다.

개발은 최소 20개의 작은 단계로 나누어 진행한다. 각 단계는 변경 내용과 확인 결과가 분명해야 하며, 단계 완료 시 개별 커밋으로 기록한다.

## 2. 원문 요구사항과 구체화한 기준

다음 항목은 PRE-PRD의 필수 요구사항이다.

| ID   | 필수 요구사항                                                  |
| ---- | -------------------------------------------------------------- |
| R-01 | Python과 pico2d로 구현한다.                                    |
| R-02 | 실행 코드는`sonic_animation_viewer.py` 단일 파일에 작성한다. |
| R-03 | 제공된`sonic-sprite.png`를 사용한다.                         |

| R-05 | 각 동작을 정확히 5회 재생한다.                                 |
| R-06 | 각 동작의 5회 재생이 끝나면 1초 쉬고 다음 동작을 재생한다.     |

## 3. 범위와 산출물

### 포함 범위

- 이미지 분석과 전체 동작·프레임 목록 작성
- 프레임별 잘라내기, 확대 및 중앙 배치
- 동작별 반복 횟수와 정지 시간 관리
- 전체 동작의 자동 순환
- 창 닫기 및 ESC 종료
- 단계별 구현, 확인 및 커밋 기록

### 제외 범위

- 캐릭터 이동을 조작하는 게임 기능
- 충돌, 점수, 사운드, 배경 스테이지
- 동작 선택 메뉴, 재생 속도 조절 UI, 재생·일시정지 버튼
- 별도 프레임 이미지 생성, 외부 프레임 데이터 파일, 추가 리소스 다운로드
- 시트의 제목·제작자 문구 및 하단의 별도 캐릭터 장식 재생

### 파일 구성

```text
Labs/LEC09/
├── PRE-PRD.md                 # 원본 요구사항
├── PRD.md                     # 개발 요구사항

단일 파일 조건은 실행 코드에 적용한다. 동작 정의, 좌표 데이터, 렌더링, 시간 처리 및 진입점을 모두 Python 파일 내부에 둔다. 원본 이미지는 수정하지 않는다.

## 4. 스프라이트 분석 요구사항

### 4.1 동작 목록

- 구현 전에 원본 이미지를 직접 확인하고 소닉의 모든 동작 그룹을 식별한다.
- 행 하나를 무조건 동작 하나로 간주하지 않는다. 시각적 동작 흐름에 따라 그룹과 프레임 순서를 결정한다.
- 기본 순서는 시트의 위에서 아래, 같은 구역에서는 왼쪽에서 오른쪽으로 한다. 연속 동작이 여러 행에 걸치는 경우 해당 프레임을 하나의 동작으로 연결한다.
- 각 동작에 고유 이름 또는 ID, 순번, 프레임 목록, 프레임당 시간을 정의한다.
- 정확한 동작 수와 좌표는 이미지 분석 단계에서 확정한다. 추정한 개수로 전체 동작 포함 여부를 판정하지 않는다.
- 제목과 크레딧을 제외한 모든 소닉 포즈가 동작 목록에 포함되었는지 원본과 대조한다. 해석이 애매한 포즈는 누락하지 않고 독립 동작 또는 관련 동작의 프레임으로 분류해 근거를 주석으로 남긴다.

### 4.2 프레임 데이터

- 균일한 격자를 가정하지 않고 프레임별 `x`, `y`, `width`, `height`를 정의한다.
- 원본 기준 좌표의 원점을 명시하고, pico2d에서 잘라 그릴 때 사용하는 좌표계와 일치하도록 변환한다.
- 모든 잘라내기 영역은 이미지 경계 안에 있어야 하고, 너비와 높이는 양수여야 한다.
- 인접 프레임이나 문구가 섞이지 않도록 하되, 손·발·회전 효과 등 해당 프레임의 구성 요소는 잘리지 않게 한다.
- 프레임별 기준점을 정의하여 크기가 다른 프레임 사이의 의도치 않은 위치 흔들림을 줄인다. 서 있는 동작은 발 위치, 구르기 등은 동작의 중심을 기준으로 보정한다.

## 5. 기능 요구사항

### F-01. 초기화와 실행

- Python과 pico2d가 설치된 환경에서 실행할 수 있어야 한다.
- 이미지 경로는 현재 터미널 위치가 아닌 `__file__`이 가리키는 코드 파일의 폴더를 기준으로 찾는다.
- 창과 이미지를 초기화한 뒤 첫 동작의 첫 프레임부터 자동 재생한다.
- 이미지 누락이나 잘못된 프레임 데이터가 있으면 원인을 알 수 있는 오류를 표시하고 종료한다.

### F-02. 프레임 재생

- 현재 동작의 프레임을 정의된 순서대로 표시한다.
- 한 동작의 첫 프레임부터 마지막 프레임까지 각각의 표시 시간을 채우면 1회 재생으로 센다.
- 마지막 프레임에 진입한 순간을 1회 완료로 세지 않는다.
- 프레임이 한 개인 동작도 정의된 프레임 표시 시간을 1회 기준으로 삼는다.
- 동작별 프레임당 시간을 코드에서 조정할 수 있게 한다. 초기값은 0.1초로 시작하고 실제 동작을 확인해 조정한다.

### F-03. 동작별 5회 반복

- 현재 동작을 처음부터 끝까지 정확히 5회 재생한다.
- 1~4회 재생을 마친 직후에는 별도의 정지 없이 같은 동작의 첫 프레임으로 돌아간다.
- 5회째 마지막 프레임의 표시 시간이 끝난 다음 정지 상태로 전환한다.
- 다음 동작으로 넘어갈 때 프레임 번호와 완료 횟수를 초기화한다.

### F-04. 동작 사이 1초 정지

- 5회 재생 후 현재 동작의 마지막 프레임을 1초 동안 유지한다.
- 마지막 프레임의 정상 표시 시간과 추가 정지 1초를 구분한다.
- 정지 중에는 프레임과 반복 횟수가 바뀌지 않는다.
- 정지 중에도 창 닫기와 ESC 입력을 처리한다. 입력 처리를 막는 1초 대기는 사용하지 않는다.

### F-05. 전체 무한 순환

- 정지 시간이 끝나면 다음 동작의 첫 프레임으로 이동한다.
- 마지막 동작도 5회 재생하고 1초 정지한 뒤 첫 동작으로 돌아간다.
- 사용자가 종료할 때까지 같은 규칙으로 자동 순환한다.

### F-06. 확대와 화면 배치

- 기본 창 크기는 1600×1200으로 시작한다.
- 원본 종횡비를 유지하고 모든 프레임에 동일한 확대 배율을 적용한다.
- 초기 배율은 6배로 시작한다. 가장 큰 프레임과 기준점 오프셋을 포함해 화면을 벗어나지 않는지 확인한 뒤 조정한다.
- 확대 후 가장 큰 프레임의 긴 변이 창의 짧은 변의 약 40~70%를 차지하도록 조정하되, 잘림 방지를 우선한다.
- 캐릭터는 화면 중앙 부근의 공통 기준 위치에 표시한다. 프레임마다 크기가 달라져도 배율은 바꾸지 않는다.
- 매 화면 갱신 시 이전 프레임을 지워 잔상이 남지 않게 한다.
- 배경색은 원본 이미지의 배경·투명도와 캐릭터의 가독성을 확인해 선택한다.

### F-07. 종료와 자원 정리

- 창 닫기 또는 ESC 입력으로 종료한다.
- 재생 중과 정지 중 모두 입력에 응답한다.
- 종료 시 pico2d 캔버스를 닫고 프로그램이 남아 실행되지 않게 한다.

## 6. 재생 상태와 시간 처리

재생 상태는 `PLAYING`과 `PAUSING`으로 구분한다. 현재 동작 번호, 프레임 번호, 완료한 재생 횟수, 현재 상태의 누적 시간을 관리한다.

| 현재 상태 | 전환 조건                                 | 처리                                                  |
| --------- | ----------------------------------------- | ----------------------------------------------------- |
| PLAYING   | 현재 프레임 시간이 끝남, 다음 프레임 있음 | 다음 프레임으로 이동                                  |
| PLAYING   | 마지막 프레임 시간 종료, 완료 횟수 5 미만 | 완료 횟수를 증가시키고 같은 동작의 첫 프레임으로 이동 |
| PLAYING   | 5회째 마지막 프레임 시간 종료             | 완료 횟수를 5로 기록하고 PAUSING으로 전환             |
| PAUSING   | 정지 시간 1초 경과                        | 다음 동작으로 이동하고 재생 상태 초기화               |
| PAUSING   | 마지막 동작의 정지 시간 1초 경과          | 첫 동작으로 이동하고 재생 상태 초기화                 |

- 시스템 시계 조정에 영향을 받지 않는 단조 증가 시간 기준으로 실제 경과 시간을 계산한다.
- 프레임 시간이나 정지 시간을 소비한 뒤 남은 시간은 다음 상태에 전달한다. 매번 누적 시간을 0으로 버려 재생이 느려지지 않게 한다.
- 한 번의 업데이트가 여러 프레임 또는 상태 경계를 넘을 경우 필요한 전환을 순서대로 처리한다.
- 렌더링 주기와 애니메이션 속도를 분리한다. 렌더링은 약 60 FPS를 목표로 하되, 동작 속도를 루프 실행 횟수에 의존시키지 않는다.
- 성능 지연 시 모든 중간 프레임의 실제 화면 출력을 보장하지는 않지만, 논리적인 재생 횟수와 동작 순서는 유지한다.

## 7. 구현 구조

단일 파일 안에서도 다음 역할은 함수와 데이터로 구분한다.

1. 설정 상수: 창 크기, 배율, 반복 횟수 5, 정지 시간 1초
2. 동작 데이터: 프레임 영역, 기준점, 재생 시간
3. 초기화 및 데이터 유효성 확인
4. 이벤트 처리
5. 경과 시간에 따른 재생 상태 갱신
6. 현재 프레임 렌더링
7. 메인 루프와 종료 처리

실행은 `if __name__ == '__main__':` 진입점을 사용한다. Python 표준 라이브러리와 pico2d 외의 런타임 의존성은 추가하지 않는다.

| 14   | 화면 지우기와 연속 렌더링 루프 구현                    | 반복 출력 시 잔상 없음                |

## 9. 인수 기준과 검증 방법

| ID   | 확인 항목         | 통과 기준                                                                               |
| ---- | ----------------- | --------------------------------------------------------------------------------------- |
| A-01 | 기술 및 파일 구성 | 실행 코드가 지정한 단일 Python 파일에 있고 pico2d로 렌더링한다.                         |
| A-02 | 실행 위치 독립성  | 저장소 루트와`Labs/LEC09`에서 실행해 같은 이미지를 불러온다.                          |
| A-03 | 전체 동작 포함    | 확정한 동작·프레임 목록과 원본을 대조해 소닉 포즈 누락이 없다.                         |
| A-04 | 프레임 영역       | 모든 프레임에서 신체·효과 잘림과 인접 포즈·문구 혼입이 없다.                          |
| A-05 | 5회 반복          | 각 동작이 첫 프레임부터 마지막 프레임까지 정확히 5회 진행한다.                          |
| A-06 | 1초 정지          | 5회째 마지막 프레임의 정상 표시 시간이 끝난 뒤 추가로 1초 유지된다.                     |
| A-07 | 동작 전환         | 정지 후 다음 동작의 첫 프레임과 초기 반복 상태에서 시작한다.                            |
| A-08 | 무한 순환         | 전체 목록을 두 번 이상 순환하며 마지막 동작에도 정지 규칙이 적용된다.                   |
| A-09 | 가독성과 배치     | 확대 기준을 충족하고 모든 프레임이 화면 안에 보이며 잔상이 없다.                        |
| A-10 | 시간 경계         | 프레임·정지 경계 직전, 정확한 경계, 직후 및 여러 경계를 넘는 입력에서 상태가 일치한다. |
| A-11 | 종료              | 재생 중과 정지 중 모두 ESC·창 닫기로 정상 종료한다.                                    |
| A-12 | 개발 기록         | 20단계 이상의 실제 단계별 변경 및 확인 기록이 커밋에 남는다.                            |

검증은 데이터 확인, 시간 계산 확인, 실제 화면 확인을 조합한다. 동작의 프레임 표시 시간 합계를 `T`라고 할 때, 해당 동작 시작부터 다음 동작 시작까지의 논리적 시간은 `5 × T + 1초`여야 한다. 전체 순환 시간은 모든 동작에 대해 이 값을 합한 시간이다.

고정 경과 시간을 넣는 상태 갱신 확인에서는 부동소수점 오차를 고려해 비교한다. 정상 부하에서 실제 화면의 정지 시간은 1초를 기준으로 렌더링 한 주기 정도의 오차를 허용한다. 재생 횟수는 관찰 또는 임시 전환 로그로 확인하며, 상시 로그 출력을 필수 기능으로 추가하지 않는다.

```
